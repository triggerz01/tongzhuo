## 一、这是什么

督学官**不持续盯着你**，而是在你不知道的时间点突然出现，采样几秒判定你在不在专注，然后消失。

一场 25 分钟的自习里可能被查 2 次，也可能 3 次，**但你永远不知道下一次是什么时候**。

### 为什么这样设计

1. **心理上更有效**——变比率强化。不可预测的抽查比持续监视更能维持行为，这是行为心理学的成熟结论。
2. **省电**——摄像头 90% 的时间是关闭的，不需要一直跑模型推理。
3. **隐私讲得清**——"我们只在巡查的那几秒读画面"，这一句在评委面前比任何技术细节都管用。

**不可预测性是这个功能的全部价值。** 如果用户能算出下次巡查什么时候来，这个功能就等于没做。

## 三、用户看到的流程

```
1. 用户设定「自习 25 分钟」，点开始
       ↓
2. 系统在这 25 分钟里随机排好 2–3 个巡查时间点（用户看不到）
       ↓
3. 到点了 —— 角色抬起头看向你，顶部出现「巡查中」
       ↓
4. 摄像头开启，采样 5 秒
       ↓
5. 判定：专注 / 离席 / 玩手机 / 犯困 / 遮挡镜头
       ↓
6. 通过 → 角色点头，继续做自己的事
   不通过 → 角色停下笔看着你（严格人格下会说话）
       ↓
7. 摄像头立即关闭
       ↓
8. 结束时结算：有效时长 → 军功币
```

## 四、巡查时间表怎么排

**不要用固定间隔，也不要纯随机。** 纯随机会出现两次挨在一起、或者半小时不查一次。

用**分层抽样**：把会话切成 N 段，每段里随机取一个时间点。既保证分散，又完全不可预测。

```
一场 M 分钟、排 N 次巡查：
  N = max(1, round(M / 10))        // 大约每 10 分钟一次
  每段长度 = M / N
  第 i 次巡查时间 = 第 i 段起点 + random(0, 段长)

约束（不满足就重排该点）：
  - 开场 3 分钟内不查（给人进入状态的时间）
  - 结束前 2 分钟内不查
  - 两次巡查间隔 ≥ 4 分钟
  - 休息期间不查，休息结束后顺延
```

## 五、前端模块接口

`renderer/patrol.js`，挂在 `window.TZ.Patrol` 下，风格参考已有的 `gate.js` / `session.js`。

```js
TZ.Patrol = {
  // 排本场的巡查表。sessionMin 是本场时长（分钟）
  plan(sessionMin, opts),

  start(),          // 开始计时
  pause(),          // 休息时暂停（巡查顺延，不作废）
  resume(),
  stop(),           // 结束本场

  // 到点了 → 通知外部去做表现（角色抬头、顶部提示）
  onInspect(cb),    // cb({ index, total })

  // 判定结果回来了
  onResult(cb),     // cb({ passed, label, index })

  state(),          // { running, done, total, nextIn, validMin }
  ledger()          // { todayCoins, validMin, cap: 30 }
};
```

**说明**：`patrol.js` 自己开一条 WebSocket 连到 `ws://127.0.0.1:8765`，直接跟感知层对话。
服务端支持多客户端连接，不会和 room.js 已有的那条冲突。这样你两端都能独立开发，不用等我们。

## 六、后端新增指令

`perception/server.py` 现在是**持续推送**模式（开始后每 500ms 广播一次状态）。
巡查需要的是**一次性取样**，所以加一条新指令。

### 请求

```json
{ "cmd": "inspect", "seconds": 5, "id": "p3" }
```

### 行为

1. 开摄像头（如果没开）
2. 采样 `seconds` 秒（按现有的 2 FPS，约 10 帧）
3. 对这些帧的判定结果取**众数**（不是取最后一帧——单帧会抖）
4. 返回结果
5. **如果这次是巡查专门开的摄像头，采样完立刻释放**

### 响应

```json
{
  "type": "inspect_result",
  "id": "p3",
  "label": "phone",
  "passed": false,
  "confidence": 0.8,
  "frames": 10,
  "detail": { "focus": 2, "phone": 8 }
}
```

`label` 沿用现有取值：`focus | away | phone | drowsy | covered`
`passed` = (`label === "focus"`)

**`covered`（遮挡镜头）判定为不通过**，不能靠挡镜头白嫖。

## 七、军功币规则

对齐 redwatch 的口径，参数写成常量方便调：

| 项 | 值 |
|---|---|
| 有效时长的计法 | 每次巡查覆盖它所在的那一段。通过 → 该段计入有效时长；不通过 → 该段作废 |
| 兑换 | 累计有效时长每满 **25 分钟** → **3 枚** |
| 每日上限 | **30 枚** |
| 存储 | `localStorage` 即可，不用上数据库。key 按日期分 |

跨天要清零当日计数（按本地日期，不是 UTC）。

## 八、验收标准

1. **不可预测性**：连续跑 3 场 25 分钟，把巡查时间点记下来，**人看不出规律**。特别检查：不能每次都在第 5 分钟、不能两次挨在 1 分钟内。
2. **摄像头真的是关的**：非巡查期间，摄像头指示灯灭、任务管理器里没有摄像头占用。**这一条是隐私卖点，必须能当场验证给评委看。**
3. **单帧抖动不影响判定**：巡查期间故意快速晃一下手机再拿开，不应判成 `phone`（取众数就能过）。
4. **遮挡不能白嫖**：巡查时用手挡住镜头 → 判定不通过。
5. **降级可用**：没有摄像头或用户拒绝授权时，跳过巡查、按纯计时发币，界面上明确标注"未开启巡查"。
6. **休息期间不查**：休息时暂停，休息结束后剩余巡查顺延。

## 十一、和主线的关系

这个模块实现的是 PRD 里的**「督学模式」**。

注意产品定位：主形态是**共场陪伴**（角色一直在，不审判），督学模式是**用户主动选择**才开启的严格模式。
自选的约束是承诺装置，有效；强加的惩罚会加重回避——这个区别在路演上要讲清楚。

所以巡查不通过时的反馈，**必须走 `renderer/gate.js` 的干预阶梯**：
第一次只是角色停下笔看你一眼（L1，不出声），不是直接开骂。
