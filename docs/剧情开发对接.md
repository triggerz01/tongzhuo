## 三、你能用的三样东西

### 1. 订阅事件 `TZRoom.on(事件, 回调)`

| 事件 | 什么时候发 | 给你什么 |
|---|---|---|
| `session-start` | 点「进入自习室」 | `{plannedMin, scene, model}` |
| `session-end` | 时长到 / 手动结束 | 完整 summary：`{reason, focusMin, elapsedMin, awayMin, phoneMin, events, points, ...}` |
| `react` | 她做出一次反应 | `{name, kind, dur}`，name 是 `praise/disappoint/lonely/welcome/sleepy/puzzled/backturn` |
| `state-change` | 感知到的状态变了 | `{label, prev}`，label 是 `focus/away/backturn/phone/drowsy/covered` |

返回值是**退订函数**，一般用不上。

### 2. 让她说话 `TZRoom.tell(文字, 选项)`

```js
TZRoom.tell('三天没见了。桌子我一直没收。', {
  recipe: 'gentleSmile',   // 表情，见下表
  level: 0.6,              // 强度 0~1
  role: 'nod',             // 动作，可省
  seconds: 3.2             // 时长；不给就按字数估
});
```

**没有音频也会驱动口型** —— 只出字幕但嘴不动，看着像弹幕不像她在说话。

可用的表情配方（`expression.js` 里的 `RECIPES`）：
`gentleSmile` `bigSmile` `sad` `frown` `sleepy` `surprised` `neutral`

可用的动作角色（`room.js` 里的 `CLIP_ROLES`）：
`praise` `disappoint` `lonely` `welcome` `lookAround` `nod` `study`

### 3. 读历史 —— 直接 import

```js
import { recordStore } from './records.js';

recordStore.all()              // { '2026-09-05': [ {...}, ... ], ... }
recordStore.ofDay('2026-09-05')
recordStore.monthList(2026, 8) // 月份从 0 开始

window.TZPoints.snapshot()     // { balance, owned, session }
window.TZPoints.owns('item_cat')
```

一条自习记录长这样：

```js
{
  endedAt, startedAt, elapsedMin, focusMin, awayMin, phoneMin, drowsyMin,
  plannedMin, awayCount, distractCount,
  events: [ {t: 23, kind: 'phone', dur: 20, shot: '176...-uqjif'}, ... ],
  reason: 'planned' | 'manual',
  scene: '自习室夜'
}
```

## 四、怎么写一条剧情

`story.js` 里已经有两条能跑的了，照着抄。结构是：

```js
{
  id: 'long_time_no_see',      // 唯一，once 用它记账
  once: false,                 // true = 一辈子只演一次
  when: (ctx) => ctx.evt === 'session-start' && (daysSinceLast() ?? 0) >= 3,
  play: () => {
    setTimeout(() => window.TZRoom.tell('三天没见了。桌子我一直没收。',
      { recipe: 'gentleSmile', level: 0.5 }), 4200);
  }
}
```

### 两个坑，先说

1. **`play` 里要 `setTimeout` 延后。** 开场那一刻她正在说「开始了，我也开始。」，
   剧情台词紧接着上去会把它顶掉。**延后 4 秒以上。**
2. **一次只演一条。** 调度器演完第一条匹配的就 return 了 —— 两个人同时说话很出戏。
   顺序重要的话，把要紧的排在 `BEATS` 数组前面。

### 调试：不用真的自习

控制台（自习室窗口按 F12）里：

```js
TZStory.beats()              // 列出所有剧情 id
TZStory.test('first_meet')   // 直接演一条，不管条件
TZStory.seen()               // 看 once 类的哪些演过了
TZStory.reset()              // 清空剧情存档，让 once 的能重演

TZRoom.tell('随便说一句', {recipe:'sad', level:0.8})   // 试台词和表情

// 造历史数据，测里程碑和"好几天没来"这类条件
TZRecords.demo()             // 铺一个月的假记录（固定种子）
TZRecords.clear()
```

## 五、三个建议做的方向（由易到难）

我在 `story.js` 里留了 TODO，展开说一下。

### A. 里程碑（最简单，先做这个）

累计专注满 60 / 300 / 1000 分钟各说一句。

- `when`: `ctx.evt === 'session-end' && totalMinutes() >= 60`，配 `once: true`
- 每个里程碑一条，id 分别是 `milestone_60` / `milestone_300` / `milestone_1000`
- **验收**：`TZRecords.demo()` 铺一个月数据后结束一场，应该弹里程碑那句

台词方向（别写成系统提示音）：
> 60 分钟：「加起来一个小时了。不多，但确实是你坐出来的。」
> 1000 分钟：「一千分钟了。你可能没算过，我算了。」

### B. 时段感（中等）

深夜（23 点后）开场换一套更轻的台词；清晨（6~8 点）换一套。

- `when`: `ctx.evt === 'session-start' && new Date().getHours() >= 23`
- 注意和 A 的顺序：里程碑更稀有，应该排在前面
- **验收**：改系统时间或临时把判断改成当前小时，能触发

台词方向：
> 深夜：「这个点了。写完这个就睡吧，我陪你写完。」

### C. 送东西（最难，但最有叙事感）

商店买了某件摆件后，**下一场开场**她"带来"并说一句。

- 需要记一个「已买但还没送达」的状态，存在 `tongzhuo.story.v1` 里
- `when`: `ctx.evt === 'session-start' && 有待送达的东西`
- `play`: `TZRoom.tell('昨天觉得桌上有点暗，我带了盏灯。')`
- **注意**：摆件要用户自己去「布置桌面」摆上去才会出现。
  台词别说成"我已经放好了"，说成"我带来了"更准确
- **验收**：商店买一件 → 回主界面 → 进自习室 → 应该说那句

> 这个想法本来就是你那个分支里的，叙事设计很好，值得捡回来。
