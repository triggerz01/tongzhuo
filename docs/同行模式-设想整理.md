## 一、你要做的是什么

**第三种模式，和「学生陪伴」「老师监督」并列。**

自习过程本身**完全照搬学生陪伴模式** —— 同一批人物（女生、男生）、
同一套识别、同一套反应、同一套点数和抓拍。**暂不做语音，只出字幕。**

不同的只有一件事：**这一次她是个人，不是一个形象。**

她有背景设定、有性格、有自己的人生目标。她因为某个原因想和你一起学习，
想和你一起变强。你们一起坐过的时间，会变成你们之间的关系。

---

## 二、这个模式的核心循环

```
   选择同行模式，选一个角色
            ↓
   准备一下 → 校准摄像头
            ↓
   ★ 不直接进自习室，先出一段文字 ★
      （前情提要：她是谁、她为什么想和你一起学）
            ↓
   进入自习室，一切和学生陪伴模式一样
            ↓
   自习结束，这段时间记两个地方：
      · 日历 / 月总结（和现在一样）
      · ★ 这个角色单独的累计时长 ★
            ↓
   累计跨过阈值 → 下次选她进来，先出下一段剧情
                  → 解锁她的专属 CG（进画廊）
                  → 中后期：她送你一件桌面摆件（商城买不到）
            ↓
   累计到最后 → 结局：她实现了人生理想，
                你们成了真正的朋友
```

**推进剧情的方式不是点击，是真的和她一起自习。**
这是整个设计最要紧的一句话 —— galgame 的结构，但"好感度"就是
你们共同坐过的时间。

## 四、需要你拍板的问题

这几个不定下来我没法动手，因为不同答案会导出完全不同的实现。

### ① 进度按什么算？—— 这个最要紧

用 **实际有效专注时长** 还是 **自习总时长**？

我强烈建议用**有效专注时长**（我们已经在记 `byLabel.focus`）。
理由：如果按总时长算，开着摄像头挂机就能刷完整条剧情线，
「和她一起进步」这个主张当场就塌了。

用有效时长的话，**你必须真的坐在那儿**，剧情才会往前走。
这恰恰是这个模式的意义。

### ② 阈值定多少？

真实体感应该是「几小时解锁一段」，但**演示时必须几分钟能看到两段剧情**，
否则评委看不到这个模式的核心。

建议：做成可配置，演示前调成很小的值（比如 3 / 8 / 15 分钟），
真实值另存一份。和 LINK 那几个阈值一样的处理。

### ③ 每个角色几段剧情？

我建议 **5 段**：

| 阶段 | 内容 |
|---|---|
| 0 | 前情提要（第一次选她时） |
| 1 | 她开始信任你，说一点真实的困扰 |
| 2 | 转折：她遇到挫折 / 差点放弃 |
| 3 | 她送你一件东西（专属摆件） |
| 4 | 结局：她做到了 |

再多写不完，再少撑不起"成长"。

### ④ 学生陪伴模式的时长算不算进同行进度？

- **算**：更宽容，用户不会觉得白坐
- **不算**：同行模式才有意义，否则"选择同行"这个动作没有分量

我倾向**不算**，但这是产品判断，你定。

### ⑤ CG 从哪来？——**这是最大的风险**

每个角色 4~5 张，两个角色就是 8~10 张。而且必须**保持角色一致**，
AI 直接生成很难做到同一个人。

三条路：
1. **VRoid 摆姿势截图 + 后期加背景** —— 一致性 100%，风格和产品统一，
   但表现力有限（我们已经打通了 `.vroidpose` 的导入流程）
2. **AI 生成** —— 好看但角色会飘，同一个人每张脸都不一样
3. **只做一个角色的 CG**，男生那条线留到赛后

我建议 **1 + 3**：先把女生一条线做完整，男生先只有文字没有 CG。

### ⑥ 剧情文本谁写？

每个角色 5 段 × 200~400 字 ≈ 2000 字。
ban-jiang 正在写路演稿，写完可以接着写这个 —— 他也想做剧情。

### ⑦ 画廊放哪？

主界面现在已经有 5 个入口（开始自习 / 学习记录 / 专注星商店 / 布置桌面 / 设置），
再加「画廊」就 6 个了，视觉上开始拥挤。

选项：放进「学习记录」里做成一个标签页，或者主界面重新分组。

## 五、能复用多少（好消息）

**几乎不用新写自习逻辑。**

| 已有 | 同行模式怎么用 |
|---|---|
| 模式切换框架 | 已经有 student / teacher 两个，加第三个是同一套代码 |
| 人物切换 + 转场 | 直接用 |
| 识别 / 反应 / 表情 / 动作 | 一行不改 |
| 点数 / 结算页 | 一行不改 |
| 日历 / 月总结 | 一行不改 |
| 桌面摆件系统 | 专属物品直接进 catalog，标记为"剧情解锁" |
| 抓拍 | 一行不改 |
| 事件总线 `TZRoom.on` | 剧情推进就挂在 `session-end` 上 |

**真正要新建的只有四样：**

1. 羁绊数据层（每个角色的累计时长 + 当前阶段 + 已解锁）
2. 剧情页（全屏文字，P5 风格，读完继续）
3. 画廊页（CG 收集）
4. **内容**：剧情文本 + CG 素材

## 六、我对排期的判断

**代码不是瓶颈，内容才是。**

骨架（数据层 + 剧情页 + 画廊 + 模式接入）我估计 **3~4 小时**能做出来并验通。
但如果没有剧情文本和 CG，它就是个空壳 —— 演示的时候点进去只有占位符，
反而不如不做。

所以建议这样切：

**必须做到的（演示能讲）**
- 同行模式能选、能进、能走完 2~3 段剧情
- 女生一条线：前情提要 + 至少 2 段中间剧情 + 至少 2 张 CG
- 画廊能看到解锁的 CG

**有余力再做**
- 第 3~4 段剧情和结局
- 专属摆件
- 男生那条线（可以只有文字没有 CG）

**明确不做**
- 同行模式的语音（你已经定了）
- 男生的 CG
